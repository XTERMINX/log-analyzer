# Log Analyzer

Консольное приложение на Python для загрузки, фильтрации и анализа серверных журналов

## Возможности

- **Импорт данных** — поддержка форматов TXT, CSV, JSON. Чтение построчное, через генераторы (без переполнения ОЗУ). Определение формата — через `parser.py`.
- **Защита от дублей** — повторный импорт файла блокируется; на уровне записей используется хэширование (`hashlib`).
- **Обработка ошибок** — битая строка не останавливает программу; ошибки логируются.
- **Поиск и фильтрация** — по временному диапазону, уровню, IP, источнику и ключевым словам; сортировка и ограничение результата; сохранение наборов фильтров (пресетов) в JSON.
- **Аналитика** — Pandas для группировок, NumPy для статистики (среднее, медиана, отклонение и т.д.), сравнение активности за разные периоды.
- **Поиск аномалий** — всплески активности с одного IP, частые ошибки, зацикленные сообщения, резкое изменение активности источника. Каждая аномалия сохраняется со своим типом, временем, источником, критичностью, причиной и связанными записями.
- **Отчёты** — полный отчёт в JSON и CSV (файлы, корректные/некорректные записи, уровни, ошибки по источникам, IP, аномалии).
- **Многозадачность** —
  - асинхронная загрузка файлов через `asyncio` + `asyncio.to_thread` (конкурентное чтение нескольких файлов);
  - бенчмарк: чтение файлов последовательно vs потоки (`ThreadPoolExecutor`), тяжёлые вычисления (SHA-256) последовательно vs процессы (`ProcessPoolExecutor`).
- **itertools/functools** — `itertools.chain` для объединения записей, `functools.lru_cache` для кэширования разбора дат.
- **Логирование** — запись действий приложения в файл с настройкой уровней (`logging`).


## Форматы логов

**TXT** — строки вида:
```
2026-09-12 10:00:00 | ERROR | server_1 | Database timeout
```

**CSV** — с заголовком `time,level,source,message,ip,code`.

**JSON** — JSON Lines (по одному объекту на строку):
```json
{"time": "2026-09-12 10:00:00", "level": "ERROR", "source": "server_1", "message": "Database timeout", "ip": "192.168.1.1"}
```

Валидные уровни: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`.

## Структура проекта

```
main.py               — точка входа, консольное меню (класс LogApp)
config.py             — настройки (пути, пороги аномалий, кол-во потоков)
modules/
  importer.py         — чтение txt/csv/json, асинхронная загрузка (Importer)
  models.py           — класс LogRecord (хэш, сериализация), итератор LogIterator
  parser.py           — определение формата файла
  analyzer.py         — статистика на Pandas/NumPy
  anomaly_detector.py — поиск аномалий (возвращает список словарей)
  statistics.py       — статистика без Pandas + сравнение периодов
  filters.py          — фильтрация, сортировка, лимит, пресеты
  storage.py          — сохранение/загрузка базы JSON (дедупликация через set)
  benchmark.py        — замер производительности (I/O + CPU)
  exporter.py         — экспорт отчётов в JSON/CSV
utils/
  helpers.py          — служебные функции, ввод дат/чисел
  validators.py       — валидация IP, дат, уровней
test_logs.py          — тесты pytest
data/
  logs/               — исходные логи
  reports/            — отчёты и результаты бенчмарка
  storage.json        — база записей
```

## Конфигурация (config.py)
| Параметр | По умолчанию | Описание |
|---|---|---|
| `THREAD_COUNT` | 4 | потоков для чтения файлов |
| `PROCESS_COUNT` | 4 | процессов для CPU-задачи |
| `ANOMALY_IP_BURST` | 40 | порог событий с одного IP за окно |
| `ANOMALY_ERROR_BURST` | 15 | порог ошибок от источника за окно |
| `ANOMALY_REPEAT_COUNT` | 10 | порог повторений сообщения |
| `ANOMALY_WINDOW_MINUTES` | 10 | окно анализа, минут |
| `ANOMALY_ACTIVITY_JUMP` | 3.0 | кратность скачка активности источника |
| `TOP_COUNT` | 5 | размер топов в отчётах |
